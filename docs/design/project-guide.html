unfold-core

A project-understanding engine that turns a repository into a structured, evidence-grounded learning guide. Roughly 45–60 minutes, adapted to intermediate level.

Project in 60 seconds

unfold-core ingests a public repository or ZIP, builds a structural and semantic model of it, and produces a guide plus a grounded chatbot — without ever executing the uploaded code.

What problem it solves

Most people can build a project faster than they can fully explain it — especially under hackathon pressure or with AI-assisted coding. This closes the gap between having the code and understanding it as a system.

Architecture

Ingestion feeds a Project IR, which branches into a Neo4j knowledge graph and a native hybrid retrieval index. Both converge into a context compiler before reaching the LangGraph orchestration layer.

Repository content is treated as untrusted input throughout — instructions found in code or comments are never followed.

Repository map

Backend analysis workers are decoupled from the API via Redis-backed jobs, so long ingestion stages don't block request handling.

# worker entrypoint
from unfold.worker import run_stage_queue

def main():
    run_stage_queue(concurrency=4)

Major subsystems

Native Hybrid RAG — BM25 and dense retrieval are fused with reciprocal rank fusion, then reranked with a local cross-encoder before graph and structural retrieval extend the result set.

LangGraph & Deep Agents — LangGraph governs deterministic and agentic branches, retries, and long-running state; Deep Agents handle open-ended investigation like architecture reconstruction.

  • Context sufficiency checks before generation
  • Hierarchical summaries for large repositories
  • Provider-independent LLM gateway (Gemini / Groq)

Security model

Repository code is never executed. ZIP handling guards against path traversal, zip bombs, and symlink escapes; detected secrets are redacted before reaching any external model.

Decisions & tradeoffs

CrewAI and MCP were intentionally excluded from the core orchestration layer in favor of a native LangGraph + Deep Agents stack, trading ecosystem breadth for tighter control over retries and state.

Interview questions

  • Why fuse BM25 and dense retrieval instead of using one alone?
  • What happens if a Gemini key is rate-limited mid-analysis?
  • Where would this architecture break at 100× repository size?
